# カット・用紙・共有・書き出し・オフライン

`CLAUDE.md` から移した機能ごとのメモ。**規則と同じ効力を持つ。** この領域を触る前に読み、分かったことはここに書き足す。

### カット

**「オブジェクト」「カット」「共有」の 3 タブ。** カットは専用タブの一覧で、
オブジェクトの一覧と同じ行の形（つまみで並べ替え・複製・ゴミ箱）。
**カット名とメモはカットタブ**、案件名は共有タブ（案件は全カット共通なので）。
並べ替えは PDF の頁の順でもある。

**見るだけ（`m=v`）ではパネルごと消えるので、カットの切り替えだけ画面の下に出す**
（`#viewercuts`）。これが無いと、複数カットを共有しても相手は 1 つしか見られない。
このリンクを**新しく作る道はもう無い**（上の「共有タブ」参照）が、配ってしまった
古いリンクのために受け側は残してある。

`state.cuts[]` が本体で、`state.items` / `state.meta` / `state.activeCam` は
**いま開いているカットの写し**。書き出す前に必ず `stashCut()` で写しを戻す
（`packState()` と `snapshot()` の頭でやっている）。**カット名を出す前にも呼ぶこと**
— 呼ばないと、名前を打ち替えてもチップが古いままになる。

共有リンクは `{v:2, project, studio, cutIx, cuts[]}`（`.json` で保存する道は
外したが、形は変えていない — 古いリンクを読むのは同じ `migrate()`）。
カットの無い旧形式（`items` が直に居るもの）は `migrate()` が 1 カットに包む。
**旧リンクは絶対に読めなくしない。**

PDF は `#papers` の中に `.paper` を並べる。1 カット 1 枚で、
`break-after:page`（最後の 1 枚を除く）で改ページする。用紙まわりの CSS を
触るときは `#paper` ではなく `.paper` セレクタであることに注意。

「カットを複製」は今の中身を写す。「新規カット」は**アプリを開いたときと同じ
中身（人ひとりとカメラ 1 台）**から始める。**空にしないこと** — カメラが無いと
ファインダーが真っ暗になり、置き直すまで何も確かめられない。

### 用紙の項目は用紙の画面に置く

用紙の向き・**記載内容**・タイトル（案件名）・範囲（このカットだけ／全カット）は、
**「PDF資料作成」を押したあとの画面**にある。パネル側に並べると、PDF を出さない人にも
ずっと見えていて、共有タブが用紙の設定で埋まる。押した人だけが見ればいい。
**そう書いた説明も要らない** — 押せば出てくる画面のことなので、共有タブから外した。
どれも押した瞬間に刷り直して見せる（`refreshSheet()`）。
**タイトルだけは打つたびに刷り直さない** — 図を全部撮り直すことになるので、
用紙の中の文字だけ差し替える（`retitleSheet()`）。

カメラ情報の欄に**「立ち位置」と「最寄りの被写体まで」は出さない**（寺村さんの指摘）。
図に人もカメラも寸法も出ているので、同じことを数字でもう一度言っているだけだった。

記載内容は 5 面（上面・側面・正面・パース・ファインダー）から選ぶ。割り付けは
`paneLayout()` が決める。

- **2 枚までは 1 列に積む。** 2 列にすると細長い枠になり、図が小さくしか入らない。
- 3 枚以上は 2 列。**枚数が奇数なら最後の 1 枚が横いっぱい**になる。
- **図は必ず「その枠の縦横比」で撮る。** 枠と比が違うと `object-fit:cover` の
  切り取りで、% で置いてある寸法ラベルが絵からずれる。`PDF_AREA` の mm から
  1 枠ぶんの mm を出して `captureView()` に渡している。
- 0 枚は作らせない（最後の 1 枚は外せない）。
- **情報欄は小さく、枠は狭く。** 図が主役なので、右の欄は 6.2pt・行間 1.35 まで
  詰めてある。`PDF_AREA` の幅（横 206mm）と CSS の `.pviews{flex}` は**必ず同じ値**に
  すること。ずれると図が枠の比と合わなくなり、寸法ラベルが絵からずれる。
- **`[data-pane]` を全部まとめて拾わない。** 用紙の中の図も `.pv[data-pane]` を
  持っているので、`.pmbar [data-pane]` に絞ること。

### 共有タブはボタンだけ

**いちばん下は紹介動画（YouTube、`https://youtu.be/pjHt0Eg4Tx4`）へのリンク**（`.ytlink`、寺村さんの指示）。
コロフォンのさらに下。**アイコンだけで、文字は付けない**（寺村さんの指示。「紹介動画を見る」は外した）。
`aria-label` と `title` に「紹介動画（YouTube）」を持たせてあるので、読み上げとホバーでは分かる。
ボタン（`.btn`）でも説明（`.hint`）でもないリンクなので、下の「7 つのボタン」「説明は 2 行」には数えない。
絵柄は YouTube のロゴを inline SVG で置いてある（外に取りに行かない）。
コロフォン（`.colophon`）は**「Studio Planner vX.Y.Z © 2026 Taichi Teramura」の 1 行で、行ごと
サイト（`https://www.taichi-teramura.com/`）へのリンク**（寺村さんの指示）。URL だけの行は置かない。
字は `.72rem` — 一度 `.62rem` にしたら小さすぎた（寺村さんの指摘）。**青文字（`--link`）で常に下線** —
灰色で下線無しだとリンクだと分からなかった（寺村さんの指摘）。`--link` は明・暗の両パレットに持つ。

**見出しを付けない。** 以前は「リンクで共有 / PDF / 画像 / プロジェクト /
まとめて書き出す」と `h2` が並んでいたが、**ボタンの名前がそのまま見出し**なので、
上に同じことをもう 1 回書いているだけだった（寺村さんの指摘）。名前のほうを
「何をするか」で言い切る形にして、見出しは全部外した。

```
[共有リンク]  [共有QRコード]
※外部3Dデータは含まれません。
[PDF資料作成]
[画像書き出し]
[HTML書き出し]
```

- **`primary`（オレンジ）を付けない。** 以前は「リンクをコピー」と「PDF保存」だけが
  オレンジで、**どれか 1 つが既定の道具であるかのように見えていた**。ここに並ぶのは
  どれも同じ重さの出口なので、色で順位を付けない。`primary` は「その画面で
  次に押すもの」（用紙の「PDF にする」、`+` の「ファイルを選ぶ」など）に取っておく。
- **「見るだけ」はもう作れない。** 共有タブのボタンも、QR の「編集できる／見るだけ」の
  切り替えも外した。**これはクラウドに 1 つの配置を置いてみんなで見る仕組みではない**
  （リンクの中に配置が丸ごと入っている）ので、見るだけは鍵にも約束にもならず、
  中途半端な機能だった（寺村さんの指摘）。**受け側は残してある** — `m=v` の付いた
  リンクを配ってしまった人が居るので、それは今までどおり読むだけで開く
  （`body.viewer` と `#viewerbar` と `#viewercuts` はそのため）。
- **URL の欄（`#linkbox`）は畳んである。** ふだんは要らない。クリップボードが
  塞がれている場所（枠の中など）で `copyLink()` が失敗したときだけ `hidden` を
  外して出し、「下の欄から手でコピーしてください」と言う。`saveHash()` は
  畳んだままでも値を入れ続けるので、出した瞬間から中身は正しい。
- **配置だけのプロジェクトファイル（.json）は外した。** 中身は共有リンクと同じ JSON で、
  **リンクを送るのと変わらなかった**（寺村さんの指摘）。持ち帰るぶんは外部3Dデータごと
  入る「HTML書き出し」があるので、そちらのほうが素直。`projectName()` は画像と
  HTML の名前づけに使うので残してある。**以前の .json を読む道は用意しない**
  （寺村さんは使っていなかったので後方互換は不要、との判断）。共有リンクの
  読み込み（`migrate()`）は別物なので、**古いリンクは今までどおり開く**。
- **リンクと QR のすぐ下に「※外部3Dデータは含まれません。」**。リンクに実体が
  乗らないのは仕様だが、渡した相手の画面で枠だけになって初めて気づくのが最悪なので、
  押す前に言う。
- **説明は 2 行だけ**。リンクの下の「※外部3Dデータは含まれません。」と、
  HTML書き出しの下の一言（`#bundlestat`。書き出しの途中経過を出す場所でもある）。
  PDF の下にあった「用紙の向き・載せる図・タイトルは、押したあとの画面で選べます。」は
  外した（寺村さんの指摘） — **押せば分かることを、押す前に読ませない**。

### 3D データ書き出し（GLB）

C4D などで続きをやるための出口。共有タブの「3Dデータ書き出し（GLB）」。

**FBX も書いていたが外した。** 寺村さんが実機で確かめたところ、**Blender では開くが
C4D は中身が空のまま開いた**。ASCII FBX を手書きする以上、読み手ごとの当たり外れを
追いかけ続けることになるので、両方で開く GLB 一本にした。**FBX 書き出しを
作り直さないこと**（`tools/fbx-to-glb.mjs` は人物モデルを*入れる*ための別の道具で、
これとは関係ない）。

実機で分かったこと（寺村さん）:

- **GLB は Blender でも C4D でも開く。**
- **テクスチャは C4D では自動で付く。Blender では付かない**（ビューポートのシェーディング
  次第。GLB の中には入っている）。
- **ボーンは C4D では正しく骨になる。Blender ではアーマチュアとして入るが、骨が
  球体で並ぶ。** glTF のジョイントは**ただのノードで骨の長さを持たない**ので、
  Blender は既定の表示にする。データとしては正しい。

#### 決めごと

- **書き出すのは現場に在るものだけ。** 寸法リボン・撮影範囲・グリッド・
  マニピュレータ・上面図の記号（`userData.plan`）・当たり判定の殻
  （`opacity: 0`）・線は入れない。**隠したもの（目のマーク）も入らない。**
- **カメラ本体とレンズは出さない**（`userData.camBody`）。向こうには本物のカメラ
  オブジェクトが立つので、その場所に箱が居ると邪魔になる（寺村さんの指示）。
  **三脚は位置の目印として残す。**
- **3DGS は入らない**（点の集まりなので）。置いてあるときはトーストで言う。
- **カメラの高さは `camY()`（`standHeight` + `y`）で出す。** 箱に乗せたカメラは
  天面ぶん上がるので、`it.y` をそのまま書くと現場と違う高さになる。
- 単位は**メートル**（glTF の標準）。倍率を掛けない。
- スキンはボーンごと出るので、**ポーズはボーンの姿勢として入る**（向こうで動かせる）。

#### 選別は visible に寄せる

`GLTFExporter` を動的 import して `scene` をそのまま渡し、**`onlyVisible` に任せる**
（`exportHide()` が一時的に消し、**必ず戻す**）。テストは「書き出しの前後で visible の
集合が同じ」ことを見ている — 戻し忘れると、書き出したあと図面から寸法や記号が消える。

**鏡（`Reflector`）は ShaderMaterial なので書き出せない。** そのあいだだけ銀色の板に
差し替える（サムネイルを焼くときと同じ手）。

#### 名前を付けてから書き出す

付けないと向こうのツリーが**「Node」「Mesh」ばかり**になって、どれが何か分からない
（寺村さんの指摘）。glTF はノードに名前を持てるので、仕様どおりのやり方。
アプリ側は名前を読まないので、**書き出しのあいだだけ付けて戻す**（`exportName()`）。

- 名前を付けるのは**メッシュと、その入れ物だけ。骨には触らない**（骨の名前は
  向こうでも骨の名前として出る）。
- **同じ名前が 2 つ以上になるときは通し番号を足す。** 「スタジオ 奥壁」が 5 枚あると
  どれがどれか分からない。
- スタジオの面は `userData.sides` から「床 / 奥壁 / 左壁 / 右壁」、天井は
  `userData.camOnly` から。それ以外は「部材」。
- カメラの group は **「カメラ 1 三脚」**。「カメラ 1」という名前は本物のカメラ
  オブジェクトに取っておく（同じ名前が 2 つ並ぶと紛らわしい）。
- **three の GLTFLoader は読み込むとき空白を `_` に均す**ので、読み返して名前を
  確かめるときは GLB の JSON を直接読むこと（ファイルの中は空白のまま正しい）。

### アンドゥ

`state` はただの JSON なので、丸ごとの控えを積むだけ（`snapshot()`）。
積むのは `saveHash()` の中の `pushUndo()` — つまり**操作が 1 つ終わったところ**で、
スライダーを動かしている最中には積まれない。60 手まで。

**起動直後に `lastSnap = snapshot()` を入れておくこと。** これが無いと最初の 1 操作が
「控えの初期化」に消えて、1 手目だけ戻せない。復元中は `restoring` を立てて
`pushUndo()` を素通しする（戻した状態をまた積んでしまう）。

### QR コード

`QR(text, forceMask)` はこのファイル内の手書き実装。バイトモード・EC L・型 1〜40。
外部ライブラリを足さないためだが、**QR は「それらしく描けている」と「読める」の
差が目で分からない**ので、テストで npm の `qrcode` と 1 モジュールずつ比べ、
`jsQR` で実際に読ませている。`forceMask` はそのための引数（アプリ側は使わない）。

書いたときに実際に踏んだ間違いを残しておく。どれも絵としては QR に見えていた。

- **生成多項式の並びが逆。** `rsPoly()` は `g[0]` が最高次でなければならない
  （`rsBytes()` が `g[0]=1` を前提に `g[i+1]` を使う）。誤り訂正語だけが化けるので、
  差分はちょうど半分くらい＝ランダムに見える。
- **BCH の割り算で見るビットがずれていた。** 形式情報は `1<<(i+10)`、
  型情報は `1<<(i+12)`。生成多項式の最高次のビットに合わせる。
- **形式情報の席を確保するとき、タイミングパターンを潰していた。**
  8 行目・8 列目のうち **6 番目はタイミング**なので飛ばす。
- **`ECB[25]` の誤り訂正語数が 30 になっていた（正しくは 26）。** 型 25 だけ落ちる。
  表を手で写したら、`qrcode` の内部表と総当たりで突き合わせること。

参照実装との比較で 1 つだけ食い違うのはマスクの選び方（減点法の 4 番目、
暗いモジュールの比率）。こちらは ISO どおりの `floor(|比率-50|/5)`、`qrcode` は
`|ceil(比率/5)-10|`。どちらも読めるので、テストは**参照実装が選んだマスクに固定して**
比べ、自動選択のほうは `jsQR` で読めることだけ見ている。

**jsQR は型 23 を読めない**（`qrcode` の出力でも読めない）。デコーダ側の不具合なので
テストでは飛ばしている。こちらの実装のせいではない。

### オフライン

Service Worker（`sw.js`）で、一度開いた端末は圏外でも開く。

- **`index.html` はネットワーク優先。** 古い版が焼き付くと直しようがない。
  圏外のときだけ控えを出す。それ以外はキャッシュ優先。
- **同一オリジンの小さなファイル（サムネイル・`poses.json`・アイコン）は控えを出しつつ裏で取り直す**
  （stale-while-revalidate）。runtime は版をまたいで残すので、これが無いと焼き直した
  サムネイルが端末に一生出ない（寺村さんの実機で、人物の一覧が古い全身のままだった）。
  **2 度目に開いたときに新しくなる。** モデル（`.glb` / `.task` / `.spz` / `.ply`）は大きいので
  今までどおりキャッシュ優先。
- **「オフラインに保存」ボタンは外した。** 何が保存されたのか誰にも見えず、
  すぐ下の「プロジェクトの保存」とも区別がつかなかった（寺村さんの指摘）。
  代わりに、置いた人物や車のモデルは**一度出したものが runtime キャッシュに残る**
  ので、実際に使った端末はそのまま圏外で開く。丸ごと持ち出すぶんは下の
  「まとめて書き出す」。
- **登録しない場所がある。** `https` か localhost で、かつ iframe の中でないときだけ。
  claude.ai のプレビュー枠には `sw.js` が無く、`file://` はそもそも許さない。
  どちらも例外を投げるだけだが、コンソールが赤くなって別の不具合と紛らわしい。
- **iPhone / iPad で圏外に備える道はこちらだけ。** 「HTML書き出し」の 1 枚は
  iOS では開けない（上の「まとめて書き出す」）。現場へ行く前に、その端末で
  **一度開いて、使う人物モデルを出しておく**こと（runtime キャッシュに残る）。
  ホーム画面に追加しておけば、アイコンから圏外でも立ち上がる。

### まとめて書き出す（1 枚の HTML）

ボタンの名前は **「HTML書き出し」**。「1 つのファイルにする」では何が起きるか
分からなかった（寺村さんの指摘）。見出しは付けない（下の「共有タブ」参照）。

取り込んだモデルも 3DGS のスキャンも、実体はこの端末の IndexedDB にある。
共有リンクにも入らないので、**渡した相手の画面では枠だけ**になる。そこで、
アプリ本体・three・部品・モデル・スキャン・配置をまるごと 1 枚の HTML に詰めて
渡せるようにした。ダブルクリックで開き、通信を 1 本も出さない。

**置いていないものも全部入れる。** 人物 14 体も車 2 種も、そのとき置いて
いなくても入れる（寺村さんの指摘）。**圏外のスタジオで開いて、そこから人を足したり
車を置いたりできないと「続きをやる」にならない。** そのぶん**素の状態で 28.5 MB**
になるが（寺村さんの実測）、現場で足せないほうが困る。

**これは PC のための出口。** 寺村さんが実機で確かめたところ、**PC では完璧に開いたが、
iPhone ではローカルに保存した HTML をブラウザで開く道が見つからなかった。**
iOS の Safari は `file://` を開けず、ファイル App から HTML をタップしても
中身を表示するだけで JavaScript は動かない。**iPhone / iPad で圏外に備えるなら、
この 1 枚ではなくホーム画面への追加（Service Worker）が本筋**（下の「オフライン」）。
画面の文言も「オフライン環境のPCで開く事が可能です。」にしてある。

**その中から出す共有リンクと QR は、必ず Web で開ける URL にする**（`shareBase()`）。
1 枚は `file://` で開くので、そのまま `location` から組むと `file:///C:/…` の
リンクになり、**受け取った人はどうやっても開けない**。1 枚を作るときに
「作った元の URL」を `__SPBUNDLE.home` に入れてあるので、そちらを使う
（公開先が変わっても追随する）。素の `index.html` を `file://` で開いた場合の
ために `WEB_HOME` も持っている。

- **file:// では ES モジュールを取りに行けない**（CORS で落ちる）。
  **data: URL のモジュールなら開ける**ので、部品はすべて data: にして importmap で
  名前を向ける。実験で確かめてから作った（`three` を data: にした 1 枚が
  `file://` で動く）。
- **data: のモジュールからは相対パスが解決できない。** `three.module.js` の
  `export * from './three.core.js'` がそれで落ちる。取り込むときに素の名前
  （`sp:3` など）へ書き換え、importmap にその名前を足す。**素の名前なら
  data: モジュールの中からでも解決できる**（これも実験で確かめた）。
- 部品は**アプリのソースそのものから拾う**。`three/addons/…` を正規表現で
  集めて、そこから import を辿る。こちらで数え上げると必ず足し忘れる。
- **取れなかったものは飛ばす**（やってはいけないこと 27）。
