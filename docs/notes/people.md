# 人物モデルとポーズ

`CLAUDE.md` から移した機能ごとのメモ。**規則と同じ効力を持つ。** この領域を触る前に読み、分かったことはここに書き足す。

### 人物モデルの入れ方

寺村さん本人が権利を持つ Tripo 生成の GLB。素の状態は 4096×4096 のテクスチャで
3 MB 前後あるので、**必ず縮めてから入れる**。1024 で見た目は変わらず 3 分の 1 になる。

`tools/*.mjs` は playwright を `test/node_modules` から引くので、先に
`cd test && npm install`、それから作業フォルダの直下に
`ln -s test/node_modules node_modules`（Windows なら test の中で実行する）。

```
node tools/shrink-glb.mjs 元.glb models/地域-服装-性別.glb 1024 0.86
node tools/make-thumbs.mjs                # models/ 全部のサムネイルを焼き直す
```

`shrink-glb.mjs` は**元が PNG でも JPEG でも読む**（Tripo 直は JPEG、Blender を
通すと PNG になる）。書き出しは常に JPEG なので、`images[0].mimeType` も一緒に
書き換えている。**中身と mimeType がずれた GLB を作らないこと。**

**入れる前に UV と骨があるか確かめる。** 見た目は正しく立っているのに、
`TEXCOORD_0`（UV）と `skins`（骨）だけが落ちていることがある。UV が無いと
テクスチャがどこにも貼れず単色になり、骨が無いとポーズが 1 つも効かない。
どちらも**後から足せない**（UV を作り直してもテクスチャは元の UV 前提で焼いてある）。

```
node -e "const b=require('fs').readFileSync(process.argv[1]);const j=JSON.parse(b.toString('utf8',20,20+b.readUInt32LE(12)));
const p=j.meshes[0].primitives[0];console.log(j.asset.generator,Object.keys(p.attributes),'skins',(j.skins||[]).length)" ファイル.glb
```

`POSITION,NORMAL,TEXCOORD_0,JOINTS_0,WEIGHTS_0` と `skins 1` が出れば入れられる。
骨は 41 本で、名前は既存 11 体と 1 つ違わず同じでなければならない（`Root` / `Hip` /
`Pelvis` / `L_Thigh` …）。**Tripo から GLB で直接落とせないときは Blender 経由でもよい**
（`generator` が `Blender Foundation Blender (stable FBX IO)` でも、UV と骨さえ
生きていれば `us-business-woman` のようにそのまま通る）。**ポリゴン削減やリメッシュは
掛けないこと** — UV とボーンウェイトが落ちる。

**FBX しか無いときは `tools/fbx-to-glb.mjs` を通す。** Tripo の「convert」で落ちてくる
`*.fbx` ＋ 隣の `*.fbm/`（テクスチャ）の組を、そのまま GLB にする。子ども 2 体は
この道で入れた。

```
node tools/fbx-to-glb.mjs 元.fbx 中間.glb     # .fbm は元の隣に置いたまま
node tools/shrink-glb.mjs 中間.glb models/asia-casual-girl.glb 1024 0.86
```

- **テクスチャの読み終わりを待つこと。** `FBXLoader.loadAsync()` が解決した時点では
  画像がまだ空で、そのまま `GLTFExporter` に渡すと
  **「No valid image data found」**で止まる。`LoadingManager` の `onLoad` まで待つ。
- FBXLoader は **Phong** でマテリアルを組む。glTF は PBR なので、色とテクスチャだけ
  引き継いで `MeshStandardMaterial`（metalness 0 / roughness 0.9）に置き換える。
  Tripo のモデルは陰影がテクスチャに焼いてあるので、これで見た目は変わらない。
- **書き出した GLB のテクスチャは PNG になる**（GLTFExporter が canvas から出すため）。
  20 MB 級になるので、**必ず `shrink-glb.mjs` を通してから** `models/` に入れる。
- 骨・UV・身長・接地はツールが測って出す。1 m と y=0 からずれていたら警告する。

登録は `PEOPLE_MODELS` に 1 行。`id` はファイル名（拡張子なし）、`kind` は
`man` / `woman` / `boy` / `girl`、`wear` はサムネイルの下に出る一語、
`label` は読み上げとツールチップ用。**ファイルは身長 1 m・A ポーズで作る**こと。
読み込み後にバウンディングボックスの高さで割って身長スライダーに合わせている。

登録は `id` / `kind` / `region`（`asia` / `af` / `us`）/ `wear`（`casual` / `business`）/
`short`（サムネイルの下に出る一語）。表示名は `modelLabel()` が 3 つから組み立てるので、
**ラベルを別に持たない**（持つと必ず食い違う）。

`+`（「オブジェクトを追加」）の「人」はこの一覧をサムネイルで並べたもの。**顔がラベル**なので、
名前を読ませない。パネルを初めて開いたときに組み立てるので、開かない人は
サムネイルを 1 枚も取りに行かない。ポーズは下の「ポーズ」参照。

**一覧に出すのはカジュアルだけ。** スーツは置いたあと、設定パネルの「服装」で
着替える（`wardrobe()` が同じ `region` + `kind` の別の服を集める）。子どもは
スーツを持っていないので、そのときは服装の欄ごと出さない。**服装はポーズの上**
（寺村さんの指示）。

**寸法表示はスタジオ以外は既定オフ**（`dimOn()`、寺村さんの指示）。選んでいる物だけ
一時的に出す（`itemLabels()`。用紙と見るだけでは出さない）。古いリンクの物は明示の
`dim: true` を持っているのでそのまま出る。

**足元のオレンジの円は選んでいるときだけ出す**（`selOnly()`、寺村さんの指示）。選択の印であって
図の一部ではないので、用紙と画像にも出ない。ライトの足元の円は上面図の記号なので今までどおり。

**サムネイルは上半身のアップ**（`make-thumbs.mjs`）。全身だと `+` の一覧で
小さすぎて誰か分からなかった（寺村さんの指摘）。モデルは身長 1 m に揃っているので、
`b.max.y * 0.90` を注視点にして距離 1.0 で切り取れば、どの体でも同じ構図になる。

### Mixamo のリグ（v1.40.0〜、まず us-business-woman 1 体）

寺村さんの「指ボーンが無いのでポージングに制限がある。モデルは Tripo、リグは別の方法に」を受けて、
**Tripo のメッシュに Mixamo で骨を付け直したモデル**を入れ始めた（Tripo には指ありの自動リグが無かった —
寺村さんの確認）。最初の 1 体は `us-business-woman`。残りは順に差し替える。

- 骨は Mixamo 名（`mixamorig:Hips` / `LeftUpLeg` / `LeftHandIndex1` …）。**アプリの正典はもともと Mixamo の名前**
  （`POSE_ORDER` / `poses.json`）なので、接頭辞（`mixamorig` ＋ `:` か `_`。GLTFExporter は `:` を落とす）を
  取ればそのまま引ける。`boneTable()` が素の名前と接頭辞なしの両方で表を作り、`POSE_MAP`（Tripo 名）で
  引けなければ正典の名前で引く。**Tripo の骨名を決め打ちしている場所は `seatBottom()` の正規表現だけ**で、
  そこにも Mixamo の同役（Hips / Spine / UpLeg）を足してある。
- **骨組みは Mixamo の「Standard Skeleton (65 bones)」**（ダウンロード画面の Skeleton LOD）。皮に効く骨は 52 本で、
  指は 5 本 × 3 関節 × 2 手（`LeftHandThumb1..3` / `Index` / `Middle` / `Ring` / `Pinky`）。最初の書き出しは
  「Thumb と Index だけ」の 34 本で、中指・薬指・小指が曲がらなかった（v1.40.0）。5 本指は v1.40.1（rev 3）から。
  **2 本指で済ませない**: 握る・指さし・ピースは残り 3 本を曲げないと作れず、URL に乗るのは曲げの数字 10 個だけ
  なので本数は共有リンクの長さに関係しない（測定: 人 5・カメラ 2・背景・箱馬・ライト 2・鏡で、全員写真ポーズ
  2,090 文字 → 指と手首を足して 2,280 文字。QR の上限は約 2,950 文字）。`boneTable()` は本数を見ない。
- **指の曲げの軸はローカル X**（このリグを three で読んだとき）。`rotation.x += 1.2` で手のひら側へ曲がる
  （`docs/pose-check/` に絵は置いていない。`test/run.mjs` ブロック 8 が距離で見ている）。
- **Mixamo の FBX は Z 上・cm・正面 -Y で出てくる**（寺村さんの書き出しは `mixamo-mini` 経由）。
  `tools/fbx-to-glb.mjs` が外形のいちばん長い軸を上にし（T ポーズでも腕の幅より背が高い）、骨から正面を出して
  +Z に向け、身長 1 m・足 y=0 に揃える。**頂点は触らず、いちばん外の group に回転と縮尺を持たせる**
  （バインド行列と皮の関係を崩さないため）。出力に `(fixed: z-up scaled 1/99.95)` と出れば直っている。
  Mixamo でリグを付けたメッシュは A ポーズのまま（Mixamo は入れたメッシュの姿勢を素の姿勢にする）なので、
  素の姿勢は Tripo と同じ見た目。
- 手順: `node tools/fbx-to-glb.mjs 元.fbx 中間.glb` → `node tools/shrink-glb.mjs 中間.glb models/<id>.glb 1024 0.86` →
  `cd test && node ../tools/make-thumbs.mjs` → **`PEOPLE_MODELS` の `rev` を上げる**。Service Worker は `.glb` を
  キャッシュ優先で持つので、`rev` を上げないと古い体が端末に居座る。`personModel()` が `?r=<rev>` を付ける。
  まとめて書き出した 1 枚（data: URL）には付けない。
- メッシュは 28k 頂点（Tripo 直の 10k より多い。Mixamo に入れた元がそれ）。1.8 MB。
- **ポーズは同じ `applyPose()` で乗る。** Tripo の体と同じポーズで関節の位置を比べると、体格差の範囲
  （最大 12 cm ほど）に収まる（ブロック 8）。差分で合わせる方式なので、Mixamo 同士でも壊れない。
- 指はまだ動かしていない（素の開いた形のまま）。次は Hand Landmarker で写真から指の曲げを取り、
  この骨に乗せる（`pose-research.md` の②）。

### 写真の手（v1.41.0〜）

寺村さんの「指ボーンで写真の手を再現したい。腕のねじれの認識も甘い」を受けて。写真から**指 5 本の曲げと
手のひらの向き**を取り、指の骨がある体（Mixamo のリグ）に乗せる。Tripo の体は数字だけ持って何もしない
（着替えて Mixamo の体になれば効く）。

- 部品は **MediaPipe Hand Landmarker**（`models/hand_landmarker.task`、7.8 MB、Apache 2.0。`LICENSE-mediapipe.txt` に
  帰属を足した）。Pose と同じ `vision_bundle.mjs` から `HandLandmarker`。押した人だけが初回に取る（合計 29 MB）。
  体の検出と並行して取りに行き、**取れなくても体のポーズは成り立つ**（失敗は握りつぶしてトーストで知らせる）。
- **全身写真では手が小さすぎて直接は当たらない。** Pose の手首・指の付け根・肘から正方形を切り出し
  （`detectHand()`。一辺は手の 3 点の広がり × 3.2 か前腕 × 1.7 の大きい方、最小 64 px）、256 px に拡大して掛ける。
  48 px の切り出しでは服の上に「手」を見つけていた。取れた手首が Pose の手首から切り出しの 35% 以上ずれていれば捨てる。
- **共有リンクに乗るのは手 1 つにつき 11 個の数字**（`it.hands = [左, 右]`、無い側は null）: 指の曲げ 5（0〜1）、
  手の向き 3（手首→中指の付け根）、手のひらの法線 3（手首・人差し指と小指の付け根の三角形）。向きは
  `poseFromLandmarks()` と同じ `(x, -y, -z)` と体の yaw で poses.json の空間に揃える（`bodyYaw()`）。
  人 5 人ぶんで 190 文字ほど。別のポーズを選ぶと `it.photo` と一緒に捨てる。形が崩れていれば `migrate()` が捨てる。
- **曲げは 3 関節の角度の和**（付け根は手のひらに対して）。開いた手でも 20 度ほどあるので 25 度を引き、200 度で 1。
  親指は 2 関節、15 度を引いて 90 度で 1。さらに 0.12 未満を 0 に寄せる（`tidy`）。アプリの描いた手で、開いた手は
  0〜0.2、握った手は 0.5〜1.0 に分かれた。**膝の上に置いた手は隠れて 0.8 と出る**（検出器が隠れた指を握りと見る）。
- **手のひらの法線は「握っていて横向き」のときだけ捨てる**（`|nCam.z| < 0.7 && 平均の曲げ > 0.5` → 0 を入れる）。
  法線の z 成分は写真の上の並びだけで決まるので手のひらか甲がカメラを向いていれば当たる。横向きの手は付け根の
  奥行きで決まり、開いた手なら当たった（内積 0.97〜0.99）が、握ると裏返った（-0.98）。法線が無いときは
  手首の曲げだけ乗せ、ひねりは `applyPose()` の肘まかせ（今までどおり）。
- **乗せ方は `applyHands()`**（`applyPose()` の後）。① 前腕をその軸まわりにひねって法線を合わせる（回内・回外。
  手首の骨だけで回すと手首がねじ切れる）→ ② 手首を曲げて手の向きを合わせる（80 度まで）→ ③ 残ったひねりを手首で →
  ④ 指を曲げる。曲げの軸は**ローカル X**（両手）、親指は **Z**（左 -・右 +、鏡写しのリグ）。関節ごとの角度は
  `CURL_K`（付け根 72 度・第 2 関節 83 度・先 54 度。親指は 32・43・32）。
- **確かめたのはアプリの描いた手だけ。** 本物の写真での当たり具合は未確認（寺村さんの実機待ち）。
  `docs/notes/tests.md` のブロック 34 が閉ループ（描く → 写真に撮る → 検出 → 数字）で見ている。

### ポーズ（実装済み）

寺村さんの C4D の FBX（`docs/pose-check/suwaru01.fbx`、椅子に座る姿）を使って、
**別リグのポーズを Tripo の 14 体に移せることを確認した。** 絵は `docs/pose-check/`。

- C4D 側は **Mixamo 系のリグ**（`mocaprig_Hips` / `Spine` / `LeftUpLeg` …、指まである）。
  Tripo 側（`Hip` / `Waist` / `Spine01` / `L_Thigh` …）とは名前も本数も違う。
- **回転をそのまま写すのは無理。** 参照元の素の姿勢（T ポーズ）が手元に無く、
  2 つのリグは初期姿勢の向きも違う。
- 通ったのは**骨の向きを合わせる方式**。親から順に、その骨から子へ向かう向きを合わせる。
  腰だけは左右の脚の位置で軸まわりのひねりも合わせないと向きが決まらない。
- **絶対の向きで合わせてはいけない（腕を除く）。** 2 つのリグは骨の置き方が違う。
  Tripo の足首→つま先は**水平**（くるぶしとつま先の骨が同じ高さ）だが、Mixamo は
  **39 度下向き**（つま先の骨が拇指球にある）。絶対で合わせると全ポーズが
  つま先立ちになる。首も Mixamo は首→頭が構造上 **17 度前傾**していて、うつむく。
  **素の姿勢からの差分**で合わせること。目標の向きは
  「この体の素の向き × 参照元が素から回ったぶん」。
- **その素の向きは、親を回す前に控えておく。** 回した後の値を使うと親の回転を
  二重に数えて、体が折り畳まれる。
- **腕だけは絶対で合わせる。** Mixamo は T ポーズ、Tripo は A ポーズで、素の姿勢が
  同じ意味を持たない。差分にすると腕が 45 度余計に下がる。`POSE_ABS` がその一覧。
- 23 関節を対応づけ、18 本を回す。男女・体型の違う体すべてで破綻しない。
  メッシュの破れも左右反転も無し。
- **取れないもの**: 骨の軸まわりのひねり（前腕のひねり、手首の向き）。Tripo に指の骨は
  無いので指も無い。打合せ用の縮尺では問題にならない。
- FBXLoader はこの C4D バイナリ FBX をそのまま読めた。
- **Mixamo から書き出した FBX は、姿勢が 1 フレームのアニメーションに入っている。**
  読んだままの骨はバインド姿勢なので、`AnimationMixer` で 0 秒を適用してから
  ワールド位置を読まないと、全員 T ポーズのままになる。C4D 経由の
  `suwaru01.fbx` はアニメーションが無く骨に焼かれていたので、両方に対応する。
- 骨の接頭辞は書き出し元で変わる（`mixamorig` / `mocaprig_`）。`Hips` で終わる骨を
  探して接頭辞を取る。
- 送っていただいた 11 ポーズ（立つ 5・座る 2・寝る 2・歩く・ダンス）は全部通った。
  `docs/pose-check/all-poses.png`、元データは `docs/pose-check/src/`。

**でき上がり**: FBX は実行時に読まない。`models/poses.json`（6 KB）に関節のワールド位置
だけを持ち、向き合わせは `applyPose()` がアプリ側でやる。14 体で 1 ファイル共通、
体格差も吸収する。人物の設定パネルにサムネイル 12 枚（素の姿勢＋11）の一覧を出し、
押すとその場で着せ替わる。`it.posture` に ID が入り、共有リンクにも乗る。

```
node tools/make-poses.mjs   # docs/pose-check/src/*.fbx -> models/poses.json + サムネイル
```

ポーズを足すときは FBX を `docs/pose-check/src/` に置き、`tools/make-poses.mjs` の
`NAMES` と `ORDER` に 1 行足して走らせる。

**縮尺は「立ったときの身長」から出す。** 座った姿勢の外形から出すと、座った人が
身長ぶんの高さまで引き伸ばされて別人の大きさになる。

**`Box3.setFromObject` はスキニングを見ない。** ジオメトリの箱を行列で移すだけなので、
骨を回しても外形が変わらない。座らせても身長のままに見えて 1 度ハマった。
`posedBox()`（`SkinnedMesh.computeBoundingBox()` を使う）を通すこと。

**`POSES` はパネルを開いたときに取りに行くので、共有リンクで開いた直後は間に合わない。**
`rebuildItems()` が「ポーズ付きの人が居るなら先に読む」を見ていて、読み終わったら
もう一度組み直す。これが無いと、共有した相手の画面だけ全員が素の姿勢で立つ。

ポーズ一覧は**設定パネルのいちばん下（向きの下）に、畳まずに置く**。以前は
身長の下で畳んであったが、畳むと在ることに気づかれなかった。

一覧に出すのは 7 種＋素の姿勢。`POSE_HIDDEN`（`stand-1` / `stand-4` / `walk` /
`dance`）は出さない。**`models/poses.json` からは消さないこと。** 古い共有リンクが
その ID を指していると、消した瞬間その人だけ素の姿勢に戻る。

**背景布の角の R は、壁と床を R のぶん切り詰めて R の面と重ならないようにしてある**
（`buildChroma()`）。重ねると端から段差と切れ目が見えた（寺村さんの指摘）。布に出ていた縞は
太陽の影のアクネで、`sun.shadow.normalBias` で逃がしている。

**R の筒は `insideOut()` で内側を表にする。** `CylinderGeometry` の法線は外向きで、`DoubleSide` なら
絵は出るが、**影の `normalBias` はジオメトリの法線で押す**。外向きのままだと光から遠ざかる側へ
押されて、R だけ自分の影に沈む（壁 130・床 151 に対して R が 104。寺村さんの指摘「R だけ暗い」）。
法線を内向きにして面の向きも裏返すと 137 で、壁と床のあいだに収まる。
**凹んだ面を CylinderGeometry で作るときは、必ずこれを通すこと。**

**「椅子」は 2 度目のデータに差し替えてある**（`docs/pose-check/src/Sitting.fbx`）。
前のものは前かがみで肘を膝に置く座り方だった。今のは背筋が伸びている
（身長 1.7 m で全体の高さ 1.30 → 1.40 m）。

**残っている癖**: 「椅子」は元データの座面が高く、身長 1.7 m で腰（`Hip`）が
**0.52 m** に来る。アプリの椅子の既定座面は 0.42 m なので、椅子の上に置くと
10 cm ほど浮く（差し替えても変わらなかった）。寺村さんの指示は「身長基準」なので
現状はそのままにしてある。

### 写真ポーズ指定（実装済み）

ポーズ一覧の最後にカメラの絵の **「写真ポーズ指定」**（寺村さんの指示）。写真を選ぶと、
写っている人の姿勢をその人物に写す。**アプリの中だけで完結する**: Google の
MediaPipe Pose Landmarker をブラウザで動かし、サーバーもアカウントも使わない。
その場でスタッフにポーズを取ってもらってスマホで撮る、という使い方が本命。

- 部品は 2 つ。**wasm（12 MB）は jsDelivr**（`MP_BASE`、版を固定）、**モデル（9.4 MB）は
  `models/pose_landmarker_full.task` に同梱**（Apache 2.0）。モデルは Google の URL から
  取ることもできたが、外に置くと消えたときに直しようがないので手元に置いた。
  **どちらも押した人だけが初回に 1 度取りに行く**（`loadPoseDetector()` の動的 import）。
  取ったものは Service Worker の runtime に残るので、2 度目からは圏外でも動く。
  初回のトーストに「21 MB」と書いてあるのはこの合計。
- **モデルは lite ではなく full。** lite は胸の前で折り畳んだ腕（ガッツポーズ）の肘を
  取り違え、腕が横に伸びて出た（寺村さんの実機確認。肘の信頼度 0.55、2D の角度 147 度）。
  full は同じ写真で 17〜20 度。3.6 MB 増えるが、腕を折った写真は現場でふつうにある。
- **推定は CPU で回す。** 1 枚の静止画なので swiftshader でも 0.3 秒。GPU は端末ごとに
  結果が変わり（同じ写真・同じモデルで lite が GPU だけ肘を外した）、静止画で
  速さの利点も無い。CPU が作れないときだけ GPU に落ちる。
- **写真の 2D 位置と、3D 推定の骨の長さ・前後の符号を組み合わせる**（`fuseLandmarks()`、
  2D 拘束の持ち上げ）。MediaPipe の 3D（`worldLandmarks`）は奥行きが甘く、full でも
  折り畳んだ肘が **90 度**まで開いた（写真の上では 20 度）。写真の上の位置は信じてよいので、
  **手足の骨だけ**「画像上の長さ」と「3D の長さ」の差から奥行きを出し、手前か奥かは
  3D の符号を借りる。縮尺（m/px）は「投影は縮むだけ」から、信頼できる骨の比の中央値。
  **胴・肩幅・腰幅・頭は 3D 推定の奥行きをそのまま使う** — 長さの差から出すと胴が
  3 度 → 28 度に傾いた。直したあと同じ写真で肘 13 度、胴 4 度。
  正面から撮った「太ももがカメラを向く」座り姿だけは、2D に長さが無いので 3D 任せになる。
- **足すのは座標だけ。** `it.posture = 'photo'` と `it.photo`（23 関節 × 3、mm 丸め）。
  向き合わせは既存の `applyPose()` をそのまま通る（`photoPoseOf()` が `POSES` と同じ形に
  包む）ので、**14 体どれにでも乗る**。共有リンクには 1 人あたり 270 文字ほど乗る。
  別のポーズを選んだら `setProp('posture')` が `it.photo` を捨てる（リンクを重くしない）。
  座標の無い `'photo'` は `migrate()` が素の姿勢に戻す。
- **33 点 → 23 関節は `poseFromLandmarks()`。** MediaPipe は x 右・y 下・z 奥
  （小さいほどカメラに近い）、poses.json は y 上・正面 +Z・左手 +X なので
  `(x, -y, -z)`。**腰の左右を X 軸に揃えて体を +Z に向ける** — 写真をどの角度から
  撮っていても、体の向きは図面の「向き」で決めるものなので、写真の向きは捨てる。
- **背骨と首の中間点は MediaPipe に無い。** 腰→肩の中点を rest と同じ割合
  （0.25 / 0.50 / 0.73）で割って `Spine` 3 つを作る。`applyPose()` は向きしか
  見ないので、長さは合わなくてよい。
- **頭の向きは耳 2 点と鼻で作る。** 最初は肩の中点→耳の中点にしていたが、
  まっすぐ立った人でも **16 度ほど前に倒れた**（MediaPipe の肩の点が耳より後ろに
  出る）。耳の左右 × 耳→鼻 の外積で頭自身の上向きを取ると、同じ絵で 0〜5 度になり、
  頭を横に向けた写真でも崩れない。
- **腕のねじれは目印で決め直す**（`TWIST_REF`、寺村さんの実機確認）。`applyPose()` は
  骨の向きを `setFromUnitVectors`（最短の回転）で合わせるので、腕を真上に上げるような
  大きな回転では**軸まわりに勝手にねじれて袖と手のひらが裏返る**。プリセットは腕が
  下がっているものばかりで出なかった。骨ごとに軸に直交する目印を持ち、素の姿勢の
  目印と目標の目印が同じ向きになるよう軸まわりで回し直す。目印は**肘・膝の曲がる向き
  （蝶番の軸。曲がりが浅いときは体の前後から出す）**、すねは**足の向き**、前腕は
  **肘と同じ**（回内は変えない）、頭は**顔の向き**。`tools/make-poses.mjs` にも同じものが
  ある（サムネイルはこれで焼き直した。`poses.json` は変わらない）。
- **`it.photo` の 24 行目は顔の向き**（鼻の向き、腰と同じ yaw で回してある）。
  頭を横に向けた写真でそちらを向く。23 行でも読める（古いリンク）。
- **奥行きは推定値。** 1 枚の写真から前後を当てているので、カメラに向けて伸ばした
  腕は縮み、真横からの写真は精度が落ちる。アプリ自身が正面から描いた「立つ」を
  読ませると胴が 14 度前に傾いたが、本物の写真（MediaPipe のテスト画像、
  ヨガの戦士のポーズ）では 3〜5 度だった。**寸法を測る道具ではない**ので、
  パネルにも「写真の奥行きは推定です」と書いてある。
- 検出は長辺 1024 に縮めてから。`<img>` で読むので EXIF の向き（スマホの縦写真）は
  ブラウザが起こす。GPU delegate が作れなければ CPU に落ちる（swiftshader では
  GPU が動くが CPU のほうが速い。実 GPU では逆のはず）。
- `<input accept="image/*">` は **MIME なので iOS でも写真とカメラがそのまま出る**
  （やってはいけないこと 28 は拡張子の一覧の話）。
- **まとめて書き出した 1 枚（file://）では、モデルを公開先（`WEB_HOME`）から取る。**
  wasm は CDN なので、どのみち通信は要る。圏外の 1 枚では「写真ポーズ指定には
  通信が必要です」と言って終わる。
- **claude.ai のプレビュー枠では動かない**（枠内から wasm もモデルも取りに行けない。
  人物モデルが出ないのと同じ理由）。確認は公開先か `python -m http.server` で。
- **横になった人は検出できないことがある**（アプリが描いた「寝る」は拾えなかった）。
  MediaPipe は立ち姿と座り姿が得意。

**実機で確かめること**: iPhone での初回の読み込み時間と検出の速さ、実際の現場写真
（ズームレンズ・逆光・複数人）での当たり具合。テストはアプリ自身が描いた人物と
上のヨガ写真でしか見ていない（寺村さんの 3 枚は手元で通したがリポジトリには入れていない）。
