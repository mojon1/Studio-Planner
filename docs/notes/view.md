# ビュー・カメラ・小窓

`CLAUDE.md` から移した機能ごとのメモ。**規則と同じ効力を持つ。** この領域を触る前に読み、分かったことはここに書き足す。

### 寸法表示はパネルのいちばん下、カメラの高さはつまみでも

**「寸法表示」はどのオブジェクトでも設定パネルの最後**（寺村さんの指示）。以前は向きの上に
居て、人物ではポーズの上、他では最後、と物によって位置が違った。向きは今までの場所。
「カメラまで」のボタンは **「カメラ距離」**。

**カメラは頭の少し上（`y + 0.14`）の 1 つで高さ**（`edgeHandles()`、`h.dy` で浮かせたぶんを引く）。
上面図では出さない。動かしたあとは `refreshCam()`（撮影範囲と小窓が追う）。

### 「パース」は「3D」

ビューボタンも PDF の記載内容も、ヒント文も **「3D」**（寺村さんの指示。英語版と揃える）。
`VIEW_NAME` / `PDF_VIEWS` / `#viewbtns` / `.pmbar` の 4 か所と、環境光のヒント。
コードの中の名前（`pers`、`persCam`）とコメントの「パース」はそのまま。

### ビューボタンの列に居る定規とグリッド

`#viewbtns` には上面〜ファインダーの 5 つと、定規（`#ruler`）・グリッド（`#gridbtn`）が並ぶ。
`syncViewBtns()` は **`button[data-view]` だけ**を回すこと。以前は全ボタンを回していたので、
起動時のビュー設定で定規とグリッドの `on` が外れ、**オンなのにボタンがグレー**で出ていた
（寺村さんの指摘）。2 つの `on` は `setDims()` / `setGrid()` が自分で持つ。テストが起動時と
ビュー切替後の両方で見ている。

### 3D ビューの見下ろし角は地面ぎりぎりまで

**止めるのは角度ではなく「視点が床に潜らないこと」**（`orbitPhiMax()`、寺村さんの指示）。
以前は `orbit.phi`（真上からの角）を 1.5 rad（水平の 4° 手前）で、次に π/2（水平ちょうど）で
止めていたが、**どちらも「4 度くらいで止まる」と見えた**。注視点（`orbit.target`）は床より上
（既定は天井高の 3 割）に居るので、水平で止めると視点もそのぶん床から浮いたままで、床の奥の縁が
数度ぶん画面の下に残る。今は視点の高さが `ORBIT_EYE_MIN`（2 cm）に着くところまで倒れる —
注視点が床の上なら水平を少し越えて見上げる角度になり、そこで床が 1 本の線になる。
`applyOrbit()` でも同じ上限を掛けるので、引いたり（`radius`）動かしたり（`target`）しても
床には潜らない。注視点を床より下へ動かしたときの下限は今までどおり π/2。
テストがドラッグで倒し切って視点の y が 0.02 になること、3 倍引いても床の上に残ることを見ている。

### 画面の移動と「中心に戻す」

**中ボタンか右ボタンのドラッグ**、または**2 本指のスワイプ**（つまむのと同時に効く）で画面を動かす。
**右ボタンは押しただけならメニュー、4 px 動いたら画面移動**（寺村さんの指示）。`contextmenu` は
Windows では離したとき、Mac では押した瞬間に来て当てにならないので、右ボタンのメニューは
`pointerup` で自分で出し（`openCtxAt`）、`contextmenu` のほうは右ボタンのあいだ（と直後 400 ms）は
捨てる。指の長押しとキーボードのメニューは今までどおり `contextmenu` から。
`panView()` に集約してあり、平行投影の 3 面はカメラを平行に動かし、パースは
**注視点（`orbit.target`）を動かす**（カメラはそこから `applyOrbit()` が組み立てる）。
**ズームと見る角度には触らない。** 動かした量は共有リンクに乗せない（見る側の都合なので）。

- 平行投影の 3 面は、以前から**何もない場所のドラッグでも動く**。パースだけは
  同じ操作が「回す」なので、そこは変えていない。動かすのは中ボタンと 2 本指。
- 動かす量は世界の大きさの 2 倍まで（`PAN_LIMIT`）。行き過ぎて迷子にならないため。
- **中ボタンは Chrome のオートスクロール（十字カーソル）を呼ぶ。** `pointerdown` だけでは
  止まらないことがあるので `mousedown` と `auxclick` でも `preventDefault` する。
- 中心からずれているあいだだけ、ビューボタンの下に**「中心に戻す」**が出る
  （`syncRecenter()` を毎フレーム呼ぶ。状態を持たず `panOffset()` から引く）。
  戻すのは位置だけで、**ズームと角度はそのまま**。

### カメラの小窓と、別ウィンドウのファインダー

右下のボタンは**目のマーク**。カメラのマークだと「撮影（シャッター）」に読めるので変えた。
**画像の書き出しボタンと取り違えられないこと**が要件で、絵柄を戻さないこと。

小窓のバーの「別ウィンドウで開く」で、ファインダーをブラウザから切り離せる。
**WebGL のキャンバスは 1 枚しか無いので、向こうで「もう一度描く」ことはできない。**
本体のキャンバスの左上にファインダーを 1 回描き、その矩形を `drawImage` で
向こうの 2D キャンバスへ写している（`drawPop()`）。本体側は直後に上から描き直すので、
1 フレームの中で終わり、ちらつきとしては出ない。renderer は
`preserveDrawingBuffer:true` なので読み出しは安全。

- **描く順を変えないこと。** `drawPop()` → 本体 → 小窓。逆にすると隅にファインダーが残る。
- **写す元は本体のキャンバスの倍率、写す先は向こうの `devicePixelRatio`。**
  別のディスプレイに出すと倍率が違う。
- 向こうが本体より大きいときは、本体に収まる最大の矩形で描いて拡大する。
  **本体のウィンドウより大きなファインダーは、そのぶん粗くなる。**
- 向こうでもドラッグでパン・チルト、ホイールで焦点距離。小窓と操作を揃えてある。
- 目のボタンで閉じると別ウィンドウも閉じる。別ウィンドウを閉じると小窓に戻る。
- **ポップアップは止められることがある**（`window.open` が null）。黙って何も
  起きないのは最悪なので、トーストで理由を言う。
- **指だけの端末では切り離しボタンを出さない。** スマホとタブレットでは
  `window.open` が別タブになり、ファインダーがまともに出ない。
  `@media (hover: none) and (pointer: coarse)` で `#pipout` を消している
  （タッチ対応のノート PC はマウスがあるので `hover: hover` になり、消えない）。

**小窓はノッチとホームバーを避ける**（`safeInset()`。寺村さんの実機で、ホーム画面から起動すると
小窓が右上のステータスバーの下に潜ってバーが掴めなかった）。`layoutPip()` が `--sat` と `--vsab` の
計算値で上下を締める。ブラウザで開いたときは両方 0 なので今までどおり。

**小窓の中身はカメラの比率そのもの**（寺村さんの指示）。黒い余白で埋めずに、箱のほうを
縦横比に合わせる。9:16 なら縦長の小窓になる。`layoutPip()` が幅から高さを出す
（バー 24 px と枠 2 px は比率の外。`pipRect()` も枠の内側を返す）。つまみで引くときは
比率を保ったまま、横に引いたぶんと縦に引いたぶん（比率で幅に換算）の大きいほうに従う。
画面比率の切替・表示中カメラの切替・カット切替で比率が変わったら、`frame()` が
`pipAspect() !== pipAr` を見て組み直す。縦長で画面に収まらないときは幅のほうを詰める。
**別ウィンドウのファインダーだけは余白を付けてよい**（`drawPop()` の letterbox はそのまま）。
`drawView()` の letterbox も残してある — ビューを「カメラ」にしたときと別ウィンドウはそれで
合わせているので、外さないこと。

**小窓の絵は自分の 2D キャンバス（`#pipcv`）に写す**（`copyPip()`。別ウィンドウと同じ手）。
WebGL のキャンバスに描いたまま小窓の中身を透明にしておくと、キャンバスより上に居る
ビューボタン（z-index 3）が小窓（z-index 4）の中に透けて見えた（寺村さんの実機。小窓を
上に寄せると「ファインダー」のボタンが小窓を貫通していた）。`frame()` は今までどおり
`pipRect()` に描き、その矩形を `drawImage` で写す。写す倍率は `renderer.getPixelRatio()`。
**WebGL のキャンバスは `#gl` で、`#view` の先頭に置く。** 小窓の中にも canvas が居るので、
`#view canvas` で拾うと 2 つ当たる（Playwright の locator は厳格なので落ちる）。テストとツールは `#gl`。

小窓が出ているかの判定は `pipShown()` に集約してある（別ウィンドウに出ているあいだは
小窓は消えるので、寸法ラベルのよけも右上の情報表示のよけも、そちらを見る）。

### 画面比率の手動設定

プリセット（`ASPECTS`）の後ろに **「手動」**（寺村さんの指示）。`it.aspect = 'custom'` と
`aspectW` / `aspectH`（横：縦の 2 つの数字。2.39:1 のような比率もそのまま打てる）。
**名前で引いていた所は全部 `aspectOf(it)` を通す**（画角・ファインダー・小窓・用紙・GLB の
カメラ）。読み値は `aspectName(it)`（手動なら `2.39:1` の形）。手動に切り替えた瞬間は今の比率の
数字から始める（16:9 なら 16 と 9）。数字が無いと絵が変わらず「効いていない」に見える。
0 以下は弾く。比率は 1/4〜4 に収める。古いリンクは `custom` を持たないのでそのまま。

### カメラのアングル

設定パネルの頭は **高さ・パン・チルト・ロール**。パンは図面のリングでも、
チルトは**カメラの頭に出る弧**（`tiltGiz`）でも変えられる。弧は視線の入っている
垂直面に置き、当たり判定は面との交点から角度で出す（レイキャストではない）。
上面ビューでは面を真上から見ることになるので出さない。

ロールは `setShotCam` の `rotation.set(pitch, rot+π, roll)` の Z。オイラー順が
`YXZ` なので、Z が視線まわりの回転になる。
