# 小道具と `+` の一覧

`CLAUDE.md` から移した機能ごとのメモ。**規則と同じ効力を持つ。** この領域を触る前に読み、分かったことはここに書き足す。

### 箱馬

`300 × 450 × 150 mm` は業界の標準寸法なので、**大きさは持たせない**。
平・横・縦の 3 通り（`it.kind`）だけ切り替える。`KOMA_AXIS` が箱の 3 辺を
どの世界軸に向けるかを持ち、`KOMA_SIZE` が外形 w×d×h を返す。置き方を変えると
`setProp` が w/d/h を引き直すので、当たり判定も「上に乗る」もそのまま効く。

形は実物（W-HS001）の写真どおり。**六面とも合板で塞いだ箱**で、天板だけが 2 枚に
割れていて手をかける溝が長手に走る。地板は少し上げてあり、側板と妻板の下端が脚になる。
**中の板に稜線を描かないこと**（`panel(..., true)`）。外板の内側と重なって
z 争いを起こし、外から線が透けて見える。既定色は合板の薄茶（`#d8c4a0`）。

### イントレ

枠組足場の櫓（寺村さんの指示）。**建枠 1.22 m × 布板 1.83 m × 1 段 1.70 m は枠組足場の
規格寸法**なので大きさは持たせず、**段数（`it.stages`、1〜4）だけ**を切り替える。
`INTRE` が寸法を、`intreDims(n)` が外形 w×d×h（ジャッキベース 0.10 m ＋ 1.70 m × 段数 ＋
布板 0.035 m）を返す。段数を変えると `setProp` が h を引き直し、`migrate()` も毎回引き直す
（規格外の段数は 1〜4 に丸める）ので、当たり判定も「上に乗る」もそのまま効く。

形は写真どおり、**丸パイプの組み合わせ**（`strut()`）。長手の両端に梯子形の建枠（支柱 2 本と
横桟 3 本、上端が横架材）、長手の 2 面に X の筋交い、いちばん下に根がらみ、脚はジャッキベース
（台皿とねじ棒）、いちばん上の支柱に連結ピン、段の継ぎ目に連結金具、天面に布板 3 枚。
`SUPPORTS` に入っているので**人もカメラも布板の上に乗る**（block 45）。線は使っていない
（やってはいけないこと 18）。既定色はグレー（`#a9b0bd`）で、パイプの色だけ変えられる。

3 段（5.24 m）以上は既定の 4.5 m の天井を突き抜ける。**わざとそのまま**にしてある — スタジオの
高さをイントレに合わせるのは現場の判断で、ここで勝手に縮めると「入らない」ことが伝わらない。

### カポック

発泡スチロールのレフ板（寺村さんの指示）。`+` では機材の列（背景布の隣）。**サブロク
910 × 1820 mm が既定**で厚さ 50 mm（`KAPOK_T`）。立て鏡と同じ「床に立てた板」で、
幅と高さはスライダー（0.3〜4 m）でも角のつまみでも変えられる（`edgeHandles` は立て鏡と同じ
下 2 角＝幅、上 2 角＝幅と高さ。範囲は `SIZE_LIM.kapok`）。寸法ラベルは辺ごと（`板幅`・`板高`、
`PANEL_SHORT` が `板`）。**基本は白**で、黒・グリーン・ブルー・グレーを `KAPOK_SWATCHES` から
選ぶ（好きな色の入力も残す）。裏面も同じ色（本物は片面黒のものもあるが、面ごとの色は持たない）。
用紙の「小道具」の行にも名前が出る。

**横向き・斜め・センチュリーで空中に**（寺村さんの指示）。パネルの「置き方」に **床から**（`it.y`、0〜4 m）・
**傾き（前後）**（`it.pitch`）・**傾き（左右）**（`it.roll`）。向きは今までどおり `rot`。
- **板の中心を軸に回し、「床から」は板のいちばん低い点の高さ**（`boardLift()` が 8 角の最低点を
  `it.y` に合わせる）。傾け直しても床に沈まず、前後 90° で床にぴたりと寝て、15° 傾けると下辺で立つ。
  「下辺の中心を軸」にすると、寝かせたときに厚みぶん床に沈む（面がピボットにあるため）ので、こうした。
- 寸法ラベルは `boardWorld()` で板に付いていく。浮かせているときは「床から X m」も出す。
- **浮かせたり傾けたりしたら角のつまみは出さない**（`edgeHandles`）。つまみの計算は床に立つ垂直な板が
  前提なので、そのときはスライダーだけ。床に立てて傾き 0 に戻せばつまみは戻る。

### ディスプレイ（画像・動画を貼る画面）

LED ウォールやモニターの見え方を確かめるため（寺村さんの指示。バーチャルプロダクションの検証）。
`+` の小道具の最後。既定は 16:9 の 3.2 × 1.8 m（LED ウォールにもモニターにも寄せやすい真ん中）で、
幅と高さは 0.2〜20 m。置き方（床から・傾き）とつまみはカポックと同じ「板」（`isBoard`、`boardPivot` /
`boardLift` / `boardWorld`。厚みは `BOARD_T`）。寸法ラベルは `画面幅`・`画面高`。

- **画面は自発光**（`MeshBasicMaterial`、`toneMapped:false`）。ライトの影響を受けず、鏡にも映る。パネルには書かない
  （説明文は v1.39.5 で「URL共有で画像や動画は含まれません。」の 1 文だけに。寺村さんの指示）。
  何も貼っていなければ暗い面に薄い枠線。
- **画像・動画のファイルは取り込んだモデルと同じ扱い。** 実体は IndexedDB（`it.key`、`{buf, mime, media:true}`）、
  **共有リンクには乗らない**（相手の画面では暗い画面と「実体はこの端末にありません」）。まとめて書き出す
  1 枚には入る（`makeBundle` の assets に `media` と `mime` を足した。`bundleFits` の勘定にも入る）。
- **URL からの読み込みは作って、外した（寺村さんの判断、v1.39.2）。作り直さないこと。** 経緯: YouTube は
  プレーヤーのページで、中の絵を取り出す手段がブラウザに無い。直リンクも置き場が CORS を許していないと
  読めない。3D ビューだけに iframe を重ねる CSS3DRenderer の道はファインダー・用紙・鏡に出ない。制約が
  多すぎるので、素材は**ファイルで読む**の 1 本にした。
- **「外す」ボタンも無い**（寺村さんの指示）。要らなければオブジェクトごと消し、差し替えは同じ
  「画像・動画を読み込む」からもう一度読む（古い実体は `setDisplayFile` が片付ける）。
- **動画は `VideoTexture`。** 繰り返し（`loop`）、`playsInline`。**音はミュートが既定**で、パネルの「ミュート」ボタン
  （押された状態＝ミュート、`it.sound`。**読み込みボタンの行のすぐ下**に、スピーカーの絵 `SND_ON` / `SND_OFF` つき。
  寺村さんの指示）で出す。音を出すのはブラウザが「操作のあと」にしか許さないので `applySound()` は
  ボタンから呼び、開き直したときに止められたらミュートへ戻す。隠したら止める（音も）。動いているあいだは
  `frame()` が `mediaLive()` を見て毎フレーム描く（このアプリは普段は必要なときだけ描く）。
  外せば止まる。**iOS で自動再生が始まるかは未確認**（muted + playsInline なら始まるはずだが実機待ち）。
- **表示の拡大縮小と位置**（v1.46.0、寺村さんの要望。実際には表示画像を拡大縮小したりずらしたりする）。パネルの「表示」に
  `拡大縮小`（`it.zoom`、10〜400 %、既定 100）と `横の位置` / `縦の位置`（`it.ox` / `it.oy`、画面の幅・高さに対する %、
  −100〜100、既定 0）。**100% 未満の余白と、ずらして空いた所は黒**（寺村さんの指示）。
  実装は `screenMat()`: `MeshBasicMaterial` の `onBeforeCompile` で `map_fragment` を差し替え、材質ごとの uniform
  （`uZoom`、`uOff`）で UV を `(uv − 0.5 − off) / zoom + 0.5` にし、0〜1 の外は黒を返す。動画の sRGB 復号の分岐
  （`DECODE_VIDEO_TEXTURE`）は three の chunk のまま残す。**テクスチャの `repeat` / `offset` は使わない** — 同じファイルを
  貼った画面どうしでテクスチャを共有しているので、片方を動かすと両方が動いてしまう。`customProgramCacheKey` は
  `'screen-view'` で固定（プログラムは 1 本、uniform は材質ごと）。3 つの数字は共有リンクに乗る。右クリックの
  「リセット」は `protoItem` の既定（100 / 0 / 0）へ。**GLB 書き出しには乗らない**（書き出しは素の `MeshBasicMaterial`。未対応）。
  正面ビューで画素を読むテストは、**選択を外してから**（選んだままだと真ん中に十字の矢印が描かれる）、既定の男性と
  カメラを隠して読む。`renderer.render()` を手で呼ぶと違う絵になるので呼ばず、`s.render()` の次のフレームを待つ。
- 貼ったら**幅を保って高さを画像の比率に合わせる**（`fitDisplay`）。あとから幅・高さを変えても勝手には
  直さない（LED ウォールの寸法が先に決まっていることがある）。「画面の比率に合わせる」で戻せる。
- ファイル選びは隠した `#mediafile`（`accept="image/*,video/*"`。画像と動画は iOS の UTI があるので
  `accept` を残してよい — やってはいけないこと 28 の対象外）。change は**選んでいるディスプレイ**に入る。
- `deleteItem` と貼り替えで、他が使っていない実体は `mediaDrop`（テクスチャ破棄・動画停止）と `idbDel`。
- GLB 書き出しには `MeshBasicMaterial` として乗る（unlit）。動画は書き出した時点の 1 コマ。**未確認。**

**曲面**（寺村さんの指示。バーチャルプロダクションの湾曲 LED ウォール）。パネルの「形」で平面／曲面
（`it.curve`）。おすすめとして決めた形は **内側（手前）に曲がる円弧**。保存は **弧長 `w`**（LED パネルの
枚数どおり。平面と切り替えても総幅が変わらない）と **半径 `it.radius`** で、弧の真ん中がオブジェクトの位置。
角度は 300° まで（それ以上は半径のほうを持ち上げる、`CURVE_MAX`）。geometry は平らな面を `bendGeo()` で
円弧に載せる（`PlaneGeometry` / `BoxGeometry` の x を弧長として、円弧の中心 `(0, 0, zFace + r)` のまわりに
回す。厚みの差はそのまま残る）。上面図の帯も弧に。寸法ラベルの「画面高」は弧の端（`boardEdge`）に付く。

**操作は弦幅と奥行**（寺村さんの指示。v1.47.0）。幅（弧長）と半径のスライダーは「どちらも図の上に見えず、
動かしても画面がどう変わるか読めない」（寺村さんの指摘）ので外し、**弦幅**（両端を結んだ直線）と
**奥行**（真ん中のへこみ）にした。どちらも上面図に見えてメジャーで測れる。`setProp('chord' / 'depth')` →
`setCurve(it, c, s)` が `r = (c²/4 + s²) / 2s` で半径と弧長に直して保存する（**保存の形は変えない**ので
古いリンクはそのまま。`setProp('radius')` も今までどおり効く）。奥行が半径を超えると 180° を越え、
上限は 300°（`curveDepthMax(c) = c × 1.87`）。**弧長と角度は数値で打てる**（v1.47.1。`setProp('arc' / 'deg')`）。弧長を打つと角度を保つ（形はそのまま、パネルの総長だけ変わる）、角度を打つと弧長を保つ（枚数はそのまま、曲がりだけ変わる）。半径は読み値（`curveInfo`）。
つまみの右クリックの「リセット」は既定の 3.2 m × 半径 5 m の弦幅 3.15・奥行 0.25。

**曲面のつまみ**（同じ指示。v1.47.0。以前は「つまみは平らな板が前提」で出していなかった）。
`edgeHandles()` の `curve:'chord' / 'depth'`、`dragCurve()`。両端の下 2 つで弦幅、両端の上 2 つで弦幅と高さ
（その端を通る垂直面との交点）、**弦の真ん中（床）の 1 つで奥行**。弦幅は**反対側の端を残して**引く
（平面の板・立て鏡と同じ手触り。相談のときは「位置を中心に左右対称」と言ったが、ほかの板と揃えた）。
奥行は弧の真ん中（位置）を残して両端が前後する。浮かせたり傾けたりしたらスライダーだけ（平面と同じ）。

**厚みと、床に敷いたら台になること**（寺村さんの指示。床に敷いた平面ディスプレイに人が埋まっていた）。
平面は「厚み」（`it.t`、0.01〜0.5 m、既定 0.08）を持つ（`boardT`）。**前後 ±90° で寝かせて左右 0° のとき
だけ台**（`displayFlat`、`isSupport`）。天面は「床から」＋厚み（`topOf`）、足元は幅 × 高さ（寝ているので
高さが奥行になる。`overTop`）。曲面は敷かないので台にならない。`SUPPORTS` は型の集合のままで、
`isSupport()` がその上に置き方を見る。

### `+` はぜんぶ絵で選ぶ

人だけでなく**小道具も機材も**サムネイルで並べる（寺村さんの指示）。名前のボタンが
並んでいるより、絵のほうが速い。

小道具と機材は GLB ではなく**アプリの中で組み立てている**ので、
`tools/make-prop-thumbs.mjs` が**アプリ自身を開いて** `+` から 1 個ずつ置き、
その group だけを別のレンダラで撮る。**形を直したら焼き直すこと。**

- **`userData.plan` の付いたものは外す。** ライトの照射くさびは長さ 4 m あるので、
  残すと外接球がそれで決まり、本体が豆粒になる。足元の円も同じ。
- **線（`isLine`）と、当たり判定の見えない殻（`opacity: 0`）も外す。**
- **鏡は別のシーンでは真っ黒になる。** `Reflector` は自分のシーンを映すものなので、
  サムネイルのあいだだけ銀色の板（`MeshStandardMaterial`）に差し替えている。
- **一覧は `asset()` を通して組み立てる。** 素の `<img src="models/…">` で書くと、
  まとめて書き出した 1 枚（`models/…` を data: に差し替える）で絵が出ない。
- 一覧はパネルを初めて開いたときに作るので、**クリックは `#addpop` で受ける**
  （個々のボタンに付けると、作る前の要素に付けることになる）。
