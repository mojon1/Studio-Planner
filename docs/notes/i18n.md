# 英語表示

`CLAUDE.md` から移した機能ごとのメモ。**規則と同じ効力を持つ。** この領域を触る前に読み、分かったことはここに書き足す。

### 英語表示

**設定は持たない**（寺村さんの指示）。ブラウザの言語が日本語でなければ英語、日本語なら
今までどおり。確認用に **`?eng`**（または `?lang=en`）を付ければ日本語のブラウザでも英語、
`?lang=ja` で日本語に戻る。`LANG` がその判定で、`navigator.language` が `ja` で始まるかだけ見る。

**ソースの文字列は日本語のまま。** 画面に出た文字を辞書（`EN`）で差し替える方式
（`translateTree()`）。起動時に文書全体を 1 度なめ、あとは `MutationObserver` が
後から出た文字（パネル・トースト・寸法ラベル・用紙・QR）を拾う。`title` / `aria-label` /
`placeholder` / `alt` / `content` の属性も見る。**アプリ側のコードに `tr()` を
書いて回らなくてよい**のがこの方式の意味で、パネルの HTML を組む関数は 1 行も変えていない。

- 数字や名前の入る文（「男性 2 奥壁まで 6.40 m」「モデルを詰めています… 3 / 20」）は
  `EN_RULES` の正規表現。それでも残った語は `EN` の語を長い順に語単位で置き換え、
  句読点を英語に直す（`trCore()`）。辞書に無いものは日本語のまま出る（壊れない）。
- **「カット」は一覧の見出しでは Shots、1 つは Shot** — `カット N` は `Shot N` にする規則が
  先に立っている。「パース」は 3D。
- **同じ値を書き戻さないこと。** 訳せず日本語が残った属性を `setAttribute` で同じ値のまま
  書くと、その mutation でまた呼ばれて**画面が固まる**（実際に固まった。ライトを置いた瞬間
  だった）。`t !== v` のときだけ書く。
- 別ウィンドウのファインダーは別 document なので、`popOut()` が `translateTree()` を
  向こうにも掛ける。`TreeWalker` は `root.ownerDocument` から作る。
- ドラッグ&ドロップの枠の文字は CSS の `content` なので、`html[lang="en"]` で差し替える。
  `document.documentElement.lang` は起動の最後で `LANG` を入れている（以前は `'ja'` 固定で、
  英語にしたつもりが `lang` だけ `ja` のままだった）。
- **文字の抜けを探すには**、`?eng` で開いて各パネルを出し、`#panel` などの中の
  テキストノードと属性から日本語の正規表現（`JP_RE`）に当たるものを拾う。
  `test/run.mjs` のブロック 37 がそれをやっている。**新しい文言を足したら `EN` にも足す。**
  足し忘れても日本語で出るだけで、テストが「残っている」と言う。
- 辞書の単語（「幅」「高さ」…）は 1 文字のものもあるので、語単位の置き換えは**長い順**。
  「人物」が「People物」にならないのはそのため。
- **ヘッドレスの Chromium は `en-US`。** 何もしないと**テストもツールも英語表示で走る**。
  `test/run.mjs` の context は全部 `locale:'ja-JP'` を既定にし、英語のブロックだけ
  `open()` の第 5 引数で上書きする。`tools/make-ogp.mjs` も同じ（英語の OGP を焼かないため）。
  実際に、日本語の文字列を見ていたテストが 7 つ落ちて気づいた。

**実機で確かめること**: 英語の iPhone / Android で開いたときに本当に英語で出るか
（ヘッドレスでは `locale:'en-US'` の context で見ただけ）。文字が長くなったぶんの
ボタンの折り返し（スクリーンショットでは PC・携帯とも収まっていた）。
