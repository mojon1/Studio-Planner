# ライト

`CLAUDE.md` から移した機能ごとのメモ。**規則と同じ効力を持つ。** この領域を触る前に読み、分かったことはここに書き足す。

### ライト

**照明のシミュレータではない。** 明るさも配光も計算しないし、ルクスもワットも
出さない。three の SpotLight / PointLight を**記号の代わり**に使って、
**幾何の質問**にだけ答えられるようにしてある。

- この高さから顔に光は届くか
- スタンドの影がホリに乗らないか
- 人の影がどっちに落ちるか
- **このライトはカメラの画角に入っていないか**

パネルにも「ライトは簡易表示です。正確なシミュレーションが必要な場合は
set.a.light 3D などの専用ソフトをお使いください。」と書いてある（寺村さんの指示）。
**この一文を外さないこと。**

#### 上面・側面・正面は図面、パースとファインダーは絵

`applyLightMood(view)` が view ごとに決める。**置いたライトを平行投影の 3 面にも
効かせると、床が色に染まって寸法も線も読めなくなる**（実際にそうなった）。
図面のほうは今までどおりの地明かりで平らに照らし、ライトは**向きと広がりの記号
（くさび）だけ**を出す。パースとファインダーはその逆で、光が乗り、記号は引っ込む
（`userData.planOnly`）。

- **本数は絶対に変えない。** three はライトの本数を**シェーダの定数**に持っているので、
  view ごとに出し入れすると全マテリアルが組み直しになる。`intensity` は uniform
  なので、0 を入れるのは安い。
- **記号は当たり判定から外す**（`planOnly()` が `noHit` も立てる）。くさびは数 m
  あるので、拾えるようにすると図面の広い範囲がライトの当たり判定になり、
  下にある物が選べなくなる。
- くさびは**光の芯が床に当たるところまで**伸ばす（`y / tan(チルト)`）。届く距離を
  そのまま描くと部屋からはみ出すし、チルトを変えても長さが変わらず記号として
  何も言っていなかった。

#### three のライトはアイテムのグループに入れない

`lightObjs`（item id → ライト）に別で持ち、`syncLights()` が値を入れ替えるだけ。
3DGS の `splatMeshes` と同じ理由。

- グループは**スライダーを動かすたびに `rebuildItem()` が作り直す**ので、中に
  入れるとシャドウマップが毎回作り直しになる。
- さらに**本数が変わるたびに全マテリアルのシェーダが組み直される**。
- 作り直すのは**種類が変わったときだけ**（スポット ⇔ 全方位はクラスが違う）。
  テストが「つまみを動かしても three のライトの uuid が変わらない」ことを見ている。

#### 影

`renderer.shadowMap` は**もともと入っていた**（太陽が影を落としている）ので、
土台を作る話ではなかった。

- **シャドウマップは 1 フレームに 1 回だけ焼く**（`shadowMap.autoUpdate = false` ＋
  `shadowNext()`）。中身は視点に依らないのに、既定では `render()` のたびに焼き直す。
  このアプリは 1 フレームに本体・小窓・別ウィンドウ・鏡と何度も `render()` を
  呼ぶので、ライトを増やすとそのぶん掛け算で効く。**`frame()` と、用紙・画像の
  書き出しが `shadowNext()` を立てる。**
- **影を落とせるのは 4 灯まで**（`LIGHT_SHADOW_MAX`）。swiftshader の実測で
  0/1/2/4 灯は 1.5 ms/frame のまま、**8 灯で 16.3 ms に跳ねた**。5 灯目からは
  光るが影は落とさない（リストの並び順で先着）。
- **全方位（中華提灯）は最初から影を落とさない。** PointLight の影は 6 面ぶん描く。

#### 型と載せ方

`LIGHT_TYPES` に 5 つ（スポット / LEDパネル / ソフトボックス / チューブ / 中華提灯）、
`LIGHT_MOUNTS` に 3 つ（スタンド / ブーム / 吊り）。

- **`+` のボタンは 1 つだけ**（スポットの絵）。型の数だけボタンを並べると追加パネルが
  煩雑になるので、**型は設定パネルで変える**（寺村さんの指示）。
- **頭は必ず (0, y, 0)、狙いはローカル +Z。** ブームでも吊りでも頭の位置は動かさず、
  支えのほうを頭からぶら下げる。図面で意味を持つのは頭の位置なので、そこを動かすと
  上面図の記号もマニピュレータも全部ずれる。
- 型を変えると**広がりとボケはその器材の既定に戻す**。スポットのまま提灯の数字が
  残っていると、選び直しても絵が変わらず「効いていない」に見える。
- **形を直したら `tools/make-prop-thumbs.mjs` を回し直すこと。**

**器材ごとに「持っているつまみ」が違う**（`LIGHT_TYPES` の 6 番目、`lightHas()`）。
持っていない器材につまみを出すと嘘になる（寺村さんの指摘）。

| | 光り方 | チルト | 広がり | ボケ | 向き |
|---|---|---|---|---|---|
| スポット | コーン | ✓ | ✓ | ✓ | ✓ |
| LEDパネル | 広いコーン（固定） | ✓ | — | — | ✓ |
| ソフトボックス | 広いコーン（固定） | ✓ | — | — | ✓ |
| チューブ | **全方位** | — | — | — | ✓（棒の向き） |
| 中華提灯 | **全方位** | — | — | — | — |

- **絞れる器材はスポットだけ。** LED パネルもソフトボックスも、広げたり絞ったり
  する仕組みを物として持っていない。
- **チューブは線光源。** コーンで出すとただのスポットライトになる。全方位なので
  狙う向きが無く、チルトも出さない。ただし**棒そのものの向きはあるので「向き」は残す**。
- 提灯は丸いので「向き」も出さない。
- チルトを持たない器材は `lightPitch()` が 0 を返す（古い値が残っていても水平）。

#### 形で踏んだ間違い（寺村さんの実機確認）

**部品を「中心と長さ」で置くと必ずどこかで繋ぎ目が空く。** 端から端へ渡す
`strut(a, b, r, m)` を通すこと。実際に 4 つ壊していた。

1. **三脚が逆さだった。** 棒の中心を外へずらして回していたので、**上が開いて下が
   すぼんだ**。`tripod()` はハブ（支柱の途中）から足へ張る。
2. **ブームの関節が 30 cm 浮いていた。** 腕の高さ（`y - 0.06`）と支柱の上端
   （`y - 0.36`）が別々の式だった。今はどちらも `top` ひとつから引く。
3. **バーンドアが宙に浮いて角度もばらばらだった。** 板の中心を前に置いて中心まわりに
   回していた。**蝶番の Group をレンズの縁に置き、板はそこから前へ出す。**
4. **ソフトボックスの形が崩れていた。** `mesh.rotation.set(π/2, 0, π/4)` の
   2 軸オイラーは順序で結果が変わる。**ジオメトリ側で `.rotateY(π/4).rotateX(π/2)`
   と順に掛ける**こと。角を上下左右に向けると断面が正方形になり、一辺は `R√2`。

**ヨークは頭と一緒に傾けない**（実物もヨークは残って中のランプが回る）。
`yoke()` は頭の外に立て、`drop` が負なら上に付く＝吊り。

#### 光源は「発光面」に置く。器材そのものは影を落とさない

**頭の原点に光源を置くと、器材の筐体の中に光源が入る。** ソフトボックスは
奥行 0.5 m の箱なので、箱が自分の光を遮って**床に真っ黒な五角形の影**を落とし、
その周りだけ明るい＝「影と光が反転した」絵になっていた（寺村さんの指摘）。
箱の側面は単面なので、**中から見ると透けて横に光が漏れる**というおまけ付き。

2 つセットで直してある。**どちらか片方だけでは直らない。**

1. **`LIGHT_TYPES` の `emit`**（スポット 0.17 / パネル 0.05 / ソフトボックス 0.46）。
   光源を頭の原点から狙いの向きへこれだけ前に出す。筐体の外へ抜ける。
2. **`fixturePart()`** — 頭の部品もヨークも `castShadow` を落とす。**器材は
   光を出すものであって遮るものではない。** 影が意味を持つのはスタンド・
   ブーム・三脚のほうなので、そちらは `shadowed()` のまま落とす。

ソフトボックスの箱は `side: DoubleSide`（単面だと中が透ける）。

#### チューブは棒に沿って 3 点

**1 点の PointLight で済ませると、どの向きから見てもただの点光源にしか
見えない**（寺村さんの指摘）。`TUBE_EMIT`（±0.46 と 0）に 3 個散らして、
近くの床や壁への当たりが「線」になるようにしてある。

- 強さは `lights.length` で割って、合計が 1 灯ぶんに揃うようにする。
- **増やしすぎないこと。** three はライトの本数をシェーダの定数に持っているので、
  チューブ 1 本につき 3 灯ぶん増える。5 点にすると滑らかになるが、3 本置いたら
  15 灯になる。
- 影は落とさない（全方位なので）ぶん、灯数が増えても描き直しは増えない。
- `lightObjs` の 1 件は**ライトの配列**を持つ（`{form, lights:[], target}`）。
  `form`（`cone` / `point` / `line`）が変わったときだけ作り直す。

#### つまみ

高さ・**チルト**・広がり・ボケ・強さ・色・向き。**チルトは今回入れたもので、
それまでライトは水平にしか向けられなかった**（`it.y` と `rot` しか持っていなかった）。

- 弧のマニピュレータはカメラと共用。**振り幅だけ違う**（カメラ ±45、ライト ±90）
  ので、`buildTiltArc()` で作り直す。
- **強さは相対の目盛り（1〜10）で単位を持たない。** パネルの説明文は v1.39.5 で外した（寺村さんの指示。数字は届く範囲を持つが、文で言わなくてよい）。 絵として読める差（キーとフィル）が
  付けばそれでよい。届く距離だけはそこから出す（`lightRange()`）。
- 色は `LIGHT_GELS` の 8 つ。**演色は合わせていない**ので、見分けるための色。
- ライトを 1 灯でも置いたら**地明かりを落とす**（`HEMI_LIT` / `SUN_LIT`）。満タンの
  ままだと置いたライトが絵の上で何も変えられず「効いていない」に見える。
  ただし真っ暗にはしない（図面として読めなくなる）。

#### 環境光のつまみ

スタジオの設定パネルに **「環境光」0〜100** が 1 本（寺村さんの指示）。ライトを 1 灯も
出していなければ **50**、1 灯でも出ていれば **25** に**自動で切り替わり、その値が
つまみに出る**。手で動かした値は、ライトの有無が切り替わるまで残す（2 灯目を足しても
動かない。全部消せば自動の 50 に戻る）。**0 で真っ暗。**

- 50 が今までの地明かり（`HEMI_OFF` / `SUN_OFF`）、25 がライトを置いたときの地明かり
  （`HEMI_LIT` / `SUN_LIT`）にちょうど当たるので、既定の見た目は 1 ミリも変わらない。
  0 → 25 → 50 → 100（OFF の 2 倍）を直線で結ぶ（`ambientGains()`）。
- **効くのは絵（パースとファインダー）だけ。** 図面（上面・側面・正面）は今までどおり
  平らに照らす。図面まで暗くすると寸法も線も読めなくなる。
- **カットごとに持つ**（`cut.ambient` / `cut.ambientLit`。`state.meta` に写す）。
  照明はカットごとに違うので。`ambientLit` は「手で入れたときライトが出ていたか」で、
  今と食い違ったら自動に戻す（`ambientLevel()` が見ている）。
- 古いリンクは `ambient` を持たないので自動のまま開く。

#### 古いリンク

古いライトは `y` と `rot` しか持っていないが、読み出しが全部既定を持っているので
**そのまま開く**（スポット・スタンド・水平）。`migrate()` には何も足していない。

#### GLB 書き出し

**置いたライトは GLB に入る**（`KHR_lights_punctual`。C4D で位置と向きがそのまま立つ）。
**アプリ自身の地明かり（太陽とヘミ）は外す** — 現場に在るものではない。
書き出しのあいだは `applyLightMood('pers')` を通して「絵」として扱う
（図面の view のまま書き出すと intensity 0 で出てしまう）。

#### やっていないこと

明るさの計算、IES、露出、演色。**「このライトで F5.6 が出ます」は言わせない。**
**3DGS には光が当たらない** — Spark のスプラットは自前のシェーダで色が焼き込んで
あるので、three のライトは 1 ミリも効かない。ロケのスキャンの中にライトを置くと、
置いた人や小道具だけが照らされて街は照らされない。
